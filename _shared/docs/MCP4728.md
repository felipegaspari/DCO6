# MCP4728 DAC (`mcp4728.h` / `mcp4728_impl.h`)

The MCP4728 I2C protocol: three chips, Fast Write encoding, attach, and the
diagnostic probe / reattach pair. Shared by the DCO4 Mainboard (STM32) and, later,
the DCO3 DCO (RP2040), which is why the driver touches no bus API of its own —
the board supplies the hooks and the driver does the rest.

Everything here is inside `#ifdef ENABLE_MCP4728`. Without that macro both
headers compile to nothing, and `mcp4728_impl.h` `#error`s if it is included
without it.

## Layout

| File | Role |
|------|------|
| `mcp4728.h` | Addresses, constants, the `extern` objects and every prototype. Include from the board that owns the chips. |
| `mcp4728_impl.h` | All definitions. Include **exactly once**, from the board shim (`MAINBOARD-CONTROLLER/MCP4728.ino`, later `DCO/MCP4728.ino`), **after** the hooks are defined. |

Arduino's prototype generator cannot see through the shim, so every cross-file
function is declared by hand in `mcp4728.h` — the same rule as the autotune and
FS `*_impl.h` pairs, described in [`SKETCH_CONTRACT.md`](SKETCH_CONTRACT.md).

## The board hooks

The shim must define all of them **before** including `mcp4728_impl.h`. They are
declared in `mcp4728.h`, so a missing one is a link error, not a compile error.

| Hook | Contract |
|------|----------|
| `void mcp_i2c_bus_begin()` | Bring the bus up: pins, clock, optional DMA init. Called from `init_MCP4728()` and again at the end of `mcp_i2c_recover()`. |
| `void mcp_i2c_recover()` | Abort, then cycle the peripheral enable and re-link DMA. Called at the top of `mcp_dac_reattach()`. |
| `void mcp_i2c_abort()` | End an in-flight transfer for real and wait, bounded, for the bus to reach idle. Must not fake the result. |
| `bool mcp_i2c_idle()` | `true` when the bus is genuinely ready. Must reflect hardware — the whole driver trusts it. |
| `bool mcp_i2c_tx(uint8_t addr7, const uint8_t* data, uint8_t n)` | Send `n` bytes to a 7-bit address. Returns whether the transfer was accepted (queued is enough — it may be asynchronous). |
| `bool mcp_i2c_tx_blocking(...)` | Same, but return only once the transfer has finished or failed. Used by the probe. |
| `void mcp_i2c_clear_error()` | Clear the error bits **only**. Never the busy/ready state. |
| `uint32_t mcp_i2c_last_error()` | Error bits latched during the last probe, printed as `err=0x…`. |
| `void mcp_diag_print(const char* s)` | Emit one diagnostic line. USB Serial on a board that has it, slim `t` chunks where the link is narrow. |
| `void mcp_after_reattach()` | Rewrite the live levels (the board's `mcpUpdate`) so a probe or reattach does not leave the outputs at the ping value. |

## Surface

| Symbol | Notes |
|---|---|
| `MCP_ADDR7[3]` | `0x63`, `0x64`, `0x65`. `MCP_CHIP_COUNT` is 3. |
| `mcp` / `mcp2` / `mcp3` | The three `MCP4728` objects, defined in the impl. |
| `mcp_present[3]` | Result of the **last** probe. Informational only. |
| `mcp_tx_buf[32]` | TX buffer, `alignas(32)` so an STM32 D-cache clean covers it. |
| `init_MCP4728()` | Bus up, attach all three, then write all twelve channels to 4095. |
| `mcp_dac_probe()` | Refresh `mcp_present[]` and print `[mcp] 0x63=ok 0x64=miss … err=0x4`. |
| `mcp_dac_reattach()` | Recover the bus, re-attach all three, `mcp_after_reattach()`, re-probe, print with a `reattach ` tag. |
| `mcp_i2c_wait_idle()` | Poll `mcp_i2c_idle()` for at most `MCP_IDLE_WAIT_US` (2 ms), then return regardless. |
| `mcp_i2c_quiesce()` | Wait for idle and, failing that, abort. Returns whether the bus is actually free. |
| `mcp_async_write(addr7, a, b, c, d)` | Fast Write of four 12-bit values. Returns `false` immediately if the bus is busy — it never blocks. |

## Both are blocking, on-demand tools

Probe and reattach run inline from the debug-command handler. Nothing polls for
them and nothing in the audio path knows they exist: they are operator tools, so
stalling the loop for a few milliseconds when a button is pressed is the point,
not a problem.

The one thing they must get right is the hand-off. The CV loop kicks an
interrupt-driven Fast Write every ~120 µs, so a probe almost always arrives with
a transfer in flight. Earlier versions forced the HAL handle to `READY` first,
which meant the blocking transfer started on a peripheral whose EV/ER interrupt
was still armed; the ISR and the blocking poll then fought over the same flags
and the resulting interrupt storm starved the main loop. That wedged the board
in both IT and DMA modes, since the event IRQ handles the address phase and NACK
in either one.

So `mcp_i2c_quiesce()` waits for real idle, and aborts the transfer for real if
idle does not arrive. If even that fails, the probe says
`bus never went idle, no ping sent` instead of reporting three absent chips.

`mcp_i2c_recover()` is the heavier hammer behind reattach: abort, then a genuine
peripheral-enable cycle. `attach()` only stores the 7-bit address, and rewriting
the handle's `State` field is bookkeeping — a slave still holding SDA is only
released by the PE cycle.

## Presence is a diagnostic, not a gate

`mcp_present[]` is deliberately not consulted by any write path. A failed ping at
1 MHz once muted the analog side for a whole run, so the driver now writes
levels unconditionally and the probe only reports. If a chip is genuinely absent
the writes are harmless; if it was a false negative, audio keeps working.

## Fast Write encoding

`mcp_fill_tx()` packs four channels as `(high nibble, low byte)` pairs, masking
each value to 12 bits — `MCP_FAST_WRITE_BYTES` (8) bytes total, no command byte.
The probe sends that full 8-byte payload rather than a truncated dummy byte or an
`IsDeviceReady` poll, so presence means "the chip ACKed a write we would really
have made". `mcp_after_reattach()` then puts the live levels back.
